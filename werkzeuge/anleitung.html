Teil 1 · Das Projekt auf GitHub hochladen

Am Ende dieses Teils liegt das Projekt im Internet und ist unter einer Adresse wie https://ihrname.github.io/chh_Chemie_7_10/ aufrufbar — von jedem Schulgerät, ohne Installation.

1 GitHub Desktop anmelden

  1. GitHub Desktop starten.
  2. Beim ersten Start fragt es nach dem Konto: Sign in to GitHub.com. Es öffnet sich der Browser, dort bestätigen Sie die Anmeldung.
  3. Danach fragt es nach Name und E-Mail. Diese beiden Angaben stehen später bei jeder Änderung dabei, die Sie hochladen. Tragen Sie ein, was auch in der Schule bekannt ist.

2 Den Standardzweig auf master stellen

Das klingt nach einer Kleinigkeit, ist aber wichtig: Das Projekt und seine automatische Prüfung erwarten einen Zweig namens master. GitHub Desktop schlägt von sich aus main vor.

  1. Menü File → Options… → Reiter Git.
  2. Bei Default branch name for new repositories auf master stellen (Feld Other…, dann master eintragen).
  3. Save.
Wenn Sie lieber main behalten Das geht auch. Sie müssen dann in Schritt 8 bei GitHub Pages main auswählen statt master. Die automatische Prüfung läuft dann allerdings nicht — sie ist auf die Namen master und develop eingestellt.

3 Den Ordner als Repository hinzufügen

Ein „Repository“ ist nichts weiter als ein Ordner, dessen Änderungen Git mitschreibt.

  1. Menü File → Add local repository…
  2. Auf Choose… klicken und den Ordner chh_Chemie_7_10 auswählen.
  3. GitHub Desktop meldet: This directory does not appear to be a Git repository. Das ist richtig so. Klicken Sie auf den Link create a repository in diesem Hinweis.
  4. Im nächsten Fenster:
    • Name: chh_Chemie_7_10 (so lassen)
    • Git ignore: None — das Projekt bringt seine eigene .gitignore mit
    • License: None
  5. Create repository.

4 Vor dem Hochladen: eine Zeile ändern

Auf dem Zweig master muss der Entwicklermodus aus sein. Ist er an, erscheint auf den Schülergeräten ein Entwicklermenü, und die automatische Prüfung schlägt fehl.

  1. Öffnen Sie assets/js/supabase-config.js in einem Texteditor (Notepad genügt).
  2. Suchen Sie die Zeile devMode: true und ändern Sie sie zu devMode: false.
  3. Speichern.
Solange Sie noch nicht mit Supabase verbunden sind Setzen Sie zusätzlich enabled: false. Dann läuft die Website vollständig, nur ohne Anmeldung und ohne Dashboard — und es wird nichts an einen Server geschickt. In Teil 2 stellen Sie es wieder auf true.

5 Die erste Fassung festschreiben

In GitHub Desktop sehen Sie links alle 456 Dateien aufgelistet. Unten links stehen zwei Felder.

  1. Ins obere Feld (Summary) schreiben Sie kurz, worum es geht, zum Beispiel: Chemie 7-10, erste Fassung
  2. Das untere Feld (Description) können Sie leer lassen.
  3. Klicken Sie auf Commit to master.

„Commit“ heißt: Dieser Stand wird als Ganzes festgehalten. Auf Ihrem Rechner, noch nicht im Internet.

6 Ins Internet hochladen

  1. Oben rechts auf Publish repository klicken.
  2. Im Fenster:
    • Name: chh_Chemie_7_10
    • Description: zum Beispiel Chemie 7–10 · Campus Hannah Höch
    • Das Häkchen bei Keep this code private muss WEG — siehe Kasten unten.
  3. Publish repository. Je nach Verbindung dauert das ein bis drei Minuten.
Privat oder öffentlich? GitHub Pages veröffentlicht nur aus öffentlichen Repositories — es sei denn, die Schule hat einen bezahlten Plan. Öffentlich heißt: Jeder kann den Programmcode und die Aufgaben lesen. Das ist bei diesem Projekt unproblematisch, denn es liegen keine Schülerdaten darin; die liegen ausschließlich in Supabase. Wenn Sie trotzdem privat bleiben wollen, brauchen Sie einen anderen Weg zur Veröffentlichung — sprechen Sie das vorher mit der Schule ab.

7 Nachsehen, ob alles angekommen ist

  1. In GitHub Desktop: Menü Repository → View on GitHub.
  2. Der Browser öffnet Ihr Repository. Sie sollten die Ordner assets, units, supabase, werkzeuge und die Datei index.html sehen.

8 Die Website einschalten (GitHub Pages)

  1. Im Repository oben auf Settings (das Zahnrad-Menü in der Kopfzeile des Repositories, nicht Ihr Profilmenü).
  2. Links in der Leiste auf Pages.
  3. Unter Build and deployment → Source: Deploy from a branch.
  4. Darunter bei Branch: master und daneben / (root) wählen.
  5. Save.

Nach ein bis zwei Minuten erscheint oben auf derselben Seite ein grüner Kasten mit der Adresse Ihrer Website.

9 Die Probe aufs Exempel

  1. Rufen Sie die Adresse aus dem grünen Kasten auf.
  2. Sie sehen die Startseite mit „Chemie Klasse 7 bis 10“ und der Liste der Unterrichtsreihen.
  3. Öffnen Sie eine Einheit, zum Beispiel FC-01 Sicher im Chemieraum. Aufgaben, Zeitplan und Hefteintrag müssen erscheinen.
Damit ist Teil 1 fertig. Die Website läuft. Sie funktioniert ab jetzt vollständig für das Lernen — Aufgaben, Videos, Übungsblätter, Hefteintrag. Was noch fehlt, ist die Anmeldung der Klasse und das Dashboard. Das ist Teil 2.

10 Künftige Änderungen hochladen

Immer derselbe Dreischritt, jedes Mal:

1. ÄndernDateien im Ordner bearbeiten wie gewohnt.
2. CommitIn GitHub Desktop kurz beschreiben, was Sie geändert haben → Commit to master.
3. PushOben auf Push origin. Nach ein bis zwei Minuten ist die Website aktualisiert.
Die Seite zeigt noch das Alte? Das Projekt speichert sich für den Offlinebetrieb im Browser zwischen. Nach einer Änderung hilft Strg + F5 (Neuladen ohne Zwischenspeicher). Auf den Schülergeräten geschieht das von selbst, sobald die Cache-Version in sw.js hochgezählt wurde.

Teil 2 · Supabase einbinden

Supabase ist die Datenbank hinter der Anwendung. Sie leistet genau drei Dinge — und nur, wenn Sie sie einschalten:

  • Die Anmeldung der Schülerinnen und Schüler über eine Freigabeliste.
  • Das Lehrerdashboard: wer ist gerade wo, wo hakt es, wer braucht eine Freigabe.
  • Die Warm-up-Ergebnisse, aus denen im Bewertungsmodus eine Note entstehen kann.
Vor dem Regelbetrieb: die Datenschutzfragen klären Ab hier verlassen personenbezogene Daten das Gerät. Was dafür geklärt sein muss — Rechtsgrundlage, Auftragsverarbeitung, Verzeichnis, Information an Eltern —, steht vollständig in DATENSCHUTZ.md, Abschnitt 5. Solange diese Punkte offen sind, lassen Sie enabled: false. Die Anwendung funktioniert ohne Supabase vollständig; es fehlt nur das Dashboard.

1 Ein Supabase-Projekt anlegen

  1. Auf supabase.com anmelden → New project.
  2. Name: zum Beispiel chemie-7-10.
  3. Database Password: ein langes Passwort erzeugen lassen und sicher notieren. Sie brauchen es selten, aber es lässt sich nicht wieder anzeigen.
  4. Region: Central EU (Frankfurt). Das ist keine Geschmacksfrage — bei einer Region außerhalb der EU müssten Sie eine Drittlandübermittlung begründen.
  5. Create new project. Die Einrichtung dauert ein bis zwei Minuten.

2 Die Datenbank einrichten

Alles, was das Projekt braucht — Tabellen, Rechte, Funktionen — steht in einer einzigen Datei im Projekt: supabase/setup.sql.

  1. Öffnen Sie supabase/setup.sql in einem Texteditor.
  2. Alles markieren (Strg + A), kopieren (Strg + C).
  3. In Supabase links auf SQL Editor → New query.
  4. Einfügen (Strg + V) und auf Run klicken (oder Strg + Enter).
  5. Unten erscheint Success. No rows returned. Das ist das gewünschte Ergebnis.
Die Datei ist so gebaut, dass Sie sie mehrfach ausführen dürfen. Vorhandene Tabellen und Daten bleiben erhalten. Wenn Sie später eine neue Fassung des Projekts einspielen, führen Sie setup.sql einfach erneut aus — genau das ist der vorgesehene Weg für Änderungen an der Datenbank.

3 Die beiden Zugangsdaten holen

  1. Links auf Project Settings (Zahnrad ganz unten) → API.
  2. Notieren Sie sich zwei Angaben:
    • Project URL — sieht aus wie https://abcdefghij.supabase.co
    • anon public — ein sehr langer Schlüssel, der mit eyJ… beginnt
Der anon-Schlüssel darf öffentlich sein. Er steht später in einer Datei, die jeder lesen kann — das ist so vorgesehen. Er erlaubt für sich genommen nichts: Jeder Schreibzugriff verlangt zusätzlich ein Sitzungstoken aus der Schüleranmeldung, und die Rechte in der Datenbank sind darauf abgestimmt.

Der service_role-Schlüssel dagegen niemals. Er steht auf derselben Seite und umgeht alle Rechte. Er gehört in keine Datei dieses Projekts und in kein Repository.

4 Die Zugangsdaten eintragen

Öffnen Sie assets/js/supabase-config.js und tragen Sie ein:

window.CHEMIE710_SUPABASE = {
  url:      'https://abcdefghij.supabase.co',   // Ihre Project URL
  anonKey:  'eyJhbGciOiJIUzI1NiIsInR5…',        // Ihr anon public key
  enabled:  true,                                // jetzt einschalten
  heartbeatSeconds: 20,
  classCode: '9',                                // Ihre Lerngruppe
  devMode:  false,                               // auf master immer false
  devClassCode: 'DEV'
};

Speichern, und in GitHub Desktop wie in Schritt 10 von Teil 1 hochladen: Commit to master → Push origin.

AngabeBedeutung
enabledfalse schaltet Supabase komplett ab — nichts verlässt das Gerät. Der Schalter für den Probebetrieb.
classCodeDie Lerngruppe, die im Dashboard voreingestellt ist. Sie können sie dort jederzeit umstellen.
devModeEntwicklermenü. Auf master immer false.

5 Ihr Lehrerkonto anlegen

Das Dashboard verlangt eine Anmeldung. Dieses Konto legen Sie in Supabase an — es hat nichts mit dem GitHub-Konto zu tun.

  1. Links auf Authentication → Users.
  2. Add user → Create new user.
  3. Dienstliche E-Mail-Adresse und ein starkes Passwort eintragen.
  4. Haken bei Auto Confirm User setzen — sonst wartet das Konto auf eine Bestätigungsmail.
  5. Create user.

6 Das Lehrerkonto freischalten

Ein Konto allein genügt nicht. Wer die Daten aller Lernenden sehen darf, muss ausdrücklich freigeschaltet werden — und jede Freischaltung wird protokolliert.

  1. SQL Editor → New query.
  2. Folgendes eintragen, die Adresse durch Ihre ersetzen, und Run:
select public.chemie710_lehrkraft_freischalten(
  'ihre.adresse@schule.de',
  'Fachlehrkraft Chemie'
);

Zurück kommt eine lange Kennung — das ist die Benutzer-ID. Fehlermeldung Kein Supabase-Konto mit der Adresse … gefunden heißt: Schritt 5 hat nicht geklappt oder die Adresse ist anders geschrieben.

Wer freigeschaltet ist, sehen Sie jederzeit mit:

select * from public.chemie710_lehrkraft_uebersicht();

7 Im Dashboard anmelden

  1. Rufen Sie …github.io/chh_Chemie_7_10/dashboard/ auf.
  2. Melden Sie sich mit der E-Mail-Adresse und dem Passwort aus Schritt 5 an.
  3. Oben rechts wechselt die Anzeige auf live mit einem grünen Punkt.
Fehlermeldung „Nur freigeschaltete Lehrkräfte …“? Dann fehlt Schritt 6. Das Konto existiert, ist aber nicht freigeschaltet.

8 Die Klasse eintragen

Schülerinnen und Schüler melden sich ohne Passwort an — mit Benutzername und Lerngruppe. Angemeldet werden kann sich nur, wer auf der Freigabeliste steht.

  1. Im Dashboard, Tafel Freigabeliste.
  2. Je Kind ausfüllen:
    • Benutzername: nachname.vorname, klein geschrieben, ohne Leerzeichen (die Form wird geprüft)
    • Anzeigename: wie es im Dashboard erscheinen soll
    • Lerngruppe: derselbe Wert für die ganze Klasse, zum Beispiel M456_9er
  3. Hinzufügen. Der Eintrag erscheint sofort in der Tabelle.
Pseudonyme statt Klarnamen? Möglich und datensparsamer: Als Anzeigename genügt ein Kürzel, das nur Sie zuordnen können. Die Anwendung braucht den echten Namen nicht.

9 Die Anmeldung ausprobieren

  1. Öffnen Sie die Website in einem privaten Fenster (Strg + Umschalt + N), damit Ihre eigene Anmeldung nicht stört.
  2. Melden Sie sich mit einem der eben angelegten Benutzernamen und der Lerngruppe an.
  3. Bearbeiten Sie eine Aufgabe.
  4. Im Dashboard muss der Name innerhalb einer Minute in der Tafel Schüleraktivität auftauchen.
Kommt der Name an, ist die Einbindung fertig. Alles Weitere — Bewertungsmodus, Freigaben, Warm-up-Noten — sind Einstellungen im Dashboard, keine Einrichtung mehr.

10 Zwei Dinge, die Sie einmal nachsehen sollten

a) Stimmt die Datenbank mit dem Sollstand überein?

Im Projekt liegt eine reine Leseprüfung. Sie ändert nichts.

  1. supabase/abgleich-readonly.sql öffnen, alles kopieren.
  2. Im SQL-Editor einfügen und Run.
  3. In der ersten Ergebnistabelle muss bei jeder Tabelle vorhanden = true und rls_aktiv = true stehen.

b) Läuft der Aufräumjob?

Die Anwendung löscht Ereignisse nach 90 und Fortschritt, Lernzeit sowie Warm-up-Ergebnisse nach 365 Tagen — aber nur, wenn der Job läuft. Ob er eingerichtet ist, zeigt das Dashboard ganz unten unter Betrieb und Datenpflege. Steht dort nichts oder etwas Überfälliges, führen Sie einmal im Monat von Hand aus:

select * from public.chemie710_aufraeumen();

GitHub Desktop: File too large oder der Push bricht ab Es ist eine Datei über 100 MB dabei. Vermutlich haben Sie den übergeordneten Ordner Chemie gewählt statt chh_Chemie_7_10. Repository entfernen (Repository → Remove) und Schritt 3 wiederholen.
Die Website zeigt 404 · There isn’t a GitHub Pages site here Pages ist noch nicht fertig oder der falsche Zweig ist eingestellt. Warten Sie zwei Minuten und prüfen Sie unter Settings → Pages, ob dort der Zweig steht, auf dem Sie tatsächlich arbeiten.
Die Seite lädt, aber es erscheinen keine Aufgaben Fast immer ein Zwischenspeicher. Strg + F5. Wenn das nicht hilft: Öffnen Sie die Entwicklerkonsole (F12) und sehen Sie unter Console nach roter Schrift.
Auf GitHub steht ein rotes Kreuz beim Commit Die automatische Prüfung hat etwas gefunden. Klicken Sie darauf — der Bericht nennt Datei und Zeile. Häufigster Fall: devMode steht auf master noch auf true.
Anmeldung: Die Anmeldung ist noch nicht mit Supabase verbunden In supabase-config.js steht enabled: false, oder URL und Schlüssel fehlen. Teil 2, Schritt 4.
Anmeldung: Benutzername wird abgelehnt Die Form muss nachname.vorname sein — genau ein Punkt, keine Leerzeichen. Und die Lerngruppe muss buchstabengenau stimmen; sie ist Teil der Anmeldung.
Dashboard: Nur freigeschaltete Lehrkräfte … Das Konto existiert, ist aber nicht freigeschaltet. Teil 2, Schritt 6.
Dashboard bleibt leer, obwohl gearbeitet wird Steht oben rechts live? Stimmt die Lerngruppe im Filterfeld mit der überein, die Sie eingetragen haben? Das ist mit Abstand der häufigste Grund.
Im Dashboard fehlt die Tafel Warm-up und Bewertung oder sie meldet einen Fehler Die Datenbank ist auf einem älteren Stand. setup.sql noch einmal ausführen — das ist gefahrlos.
